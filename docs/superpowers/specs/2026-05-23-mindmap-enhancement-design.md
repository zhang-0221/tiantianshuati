# Mind Map Enhancement Design

## Goal

Improve the mind map feature so newly generated maps are richer, more useful for study, and visually clearer while preserving the existing horizontal mind map experience.

The change targets only newly generated outlines. Existing saved exams and outlines should not be rewritten or expanded automatically.

## Current Context

The app is a single-file HTML application in `index.html`.

Mind map data is generated by `SYS_PROMPT_OUTLINE`, parsed from the AI response as `outline`, enriched by `enrichOutline()`, linked to questions by `autoLinkQuestions()`, and rendered in the mind map tab through Markmap with an HTML tree fallback.

The current implementation already supports:

- Saved outlines on exams.
- Markmap rendering with zoom, expand, collapse, search, fullscreen, PNG export, and Markdown export.
- Node details with description, key points, mastery stats, and practice entry.
- Mastery coloring based on linked question results.

The weak points are:

- Generated outlines can be too shallow or sparse.
- The prompt asks for detail but does not enforce a stable knowledge decomposition pattern strongly enough.
- The renderer mostly shows node titles, so descriptions and key points are hidden until a node is clicked.
- Visual hierarchy is subdued, making large maps feel plain.

## Selected Approach

Use approach C: improve generation, add quality checks, and polish the mind map presentation.

This keeps the traditional horizontal mind map as the main view. It does not replace the feature with a card-based outline or a separate knowledge base view.

## Generation Design

Update the outline prompt so new outlines follow a stable learning-oriented hierarchy:

1. Top level: source chapters, sections, or major topics from the material.
2. Second level: knowledge modules under each topic.
3. Third level: concrete concepts, mechanisms, rules, formulas, procedures, comparisons, or cases.
4. Fourth level: definitions, conditions, steps, exceptions, common mistakes, and exam-style angles.

New outline requirements:

- Target at least 40 outline nodes when the material has enough content.
- Target a maximum depth of at least 4 levels for substantial material.
- Keep titles short and concrete.
- Avoid empty labels such as "other", "related content", "summary", or "misc".
- Leaf nodes must be specific enough to practice directly.
- Leaf nodes should include 2-4 `keyPoints`.
- Non-leaf nodes may include a short `description` and can leave `keyPoints` empty.
- Every question should still include `outlineNodeId`.

The prompt must still require all questions and outline nodes to be grounded in the provided material.

## Quality Checks

Add a validation step after parsing AI output and before saving a new exam.

The validator should compute:

- Total outline node count.
- Maximum outline depth.
- Number of leaf nodes.
- Number of leaf nodes missing key points.
- Empty or generic node titles.

For new outlines, reject clearly underdeveloped outlines:

- Fewer than 20 nodes when the source material has at least 1,000 Chinese characters or 700 Latin words.
- Maximum depth below 3.
- Most leaf nodes have no key points.

When validation fails, show a user-facing error that the knowledge outline is too simple and suggest regenerating. The app should not save the low-quality outline.

Keep `enrichOutline()` for light normalization such as IDs and missing arrays, but do not use it to invent new knowledge content.

## Visual Design

Keep Markmap as the primary renderer and the HTML tree as fallback.

Markmap improvements:

- Default expand level should be 3 levels instead of 2.
- Main branches should receive distinct, restrained colors.
- Higher-level nodes should read as stronger anchors than leaf nodes.
- Node labels should include compact secondary information when available, such as short description or linked question count.
- Mastery status should remain visible and should not conflict with branch colors.
- Search highlighting should be restored cleanly after search text is cleared.

Node detail panel improvements:

- Present the selected node as a compact knowledge card.
- Show title, description, key points, linked question count, answered count, accuracy, and practice button.
- Keep it readable on mobile and avoid covering too much of the map.

Fallback tree improvements:

- Use clearer indentation, branch lines, and level-specific styling.
- Show description and key point hints without making the tree too wide.
- Preserve expand, collapse, search, and node-detail behavior.

## Data Flow

1. User imports or pastes material and enables knowledge outline generation.
2. `generateExam()` calls `callAI()` with the enhanced outline prompt.
3. `parseAIResponse()` parses `questions` and `outline`.
4. `enrichOutline()` normalizes IDs and required fields.
5. New validator checks outline richness.
6. If valid, `autoLinkQuestions()` links questions to outline nodes.
7. The exam is saved with the richer outline.
8. Opening the mind map renders the outline with improved visual hierarchy and node details.

## Error Handling

If the AI response cannot be parsed, preserve the existing JSON parse error behavior.

If outline validation fails, show a specific error message rather than saving a poor outline. The generated questions can be discarded with the failed response to keep the saved exam consistent.

If Markmap fails to load or render, fall back to the improved HTML tree.

If a node has no linked questions, the detail panel should show that state clearly and hide the practice button.

## Testing

Manual verification should cover:

- Generating a new exam with outline enabled.
- Confirming new outline data has enough nodes, depth, and leaf key points.
- Opening the mind map and checking visual hierarchy, expand/collapse, search, node detail, fullscreen, and export.
- Confirming old saved outlines still open without migration.
- Confirming fallback tree still works when Markmap is unavailable.

Because this is a single-file browser app without an existing automated test harness, add small pure helper functions where possible so outline validation can be checked from the browser console or a local script without calling the AI API.

## Out Of Scope

- Rewriting or expanding old saved outlines.
- Adding a separate graph database or knowledge-base editor.
- Replacing Markmap with another visualization library.
- Adding server-side generation.
- Changing the core quiz generation behavior beyond the `outlineNodeId` linkage requirements.
